# Щоденне порівняння цін: Садовий Рай і Водоспад

Щоранку GitHub сам завантажує ваш фід із SalesDrive і фід Водоспаду, знаходить товари, які є в обох, і порівнює ціни. Знімок цін зберігається щодня, тому видно, коли і на скільки постачальник змінював ціну. Товари, з якими треба щось зробити, підсвічуються червоним.

## Що лежить у репозиторії

| Файл або папка | Для чого |
|---|---|
| `README.md` | короткий звіт на головній сторінці репозиторію, оновлюється після кожного запуску |
| `report.xlsx` | повний звіт: порівняння, журнал змін, ціни по днях, пари на перевірку, підсумок |
| `docs/index.html` | дашборд з фільтрами, пошуком і графіками цін |
| `data/snapshots/` | знімок цін за кожен день, один CSV на дату |
| `data/changes.csv` | журнал усіх змін цін: дата, хто змінив, було, стало |
| `mapping/suggestions.csv` | сумнівні пари, які чекають вашого рішення |
| `mapping/mapping.csv` | ваші ручні правила зіставлення |
| `config.json` | список постачальників, пороги, налаштування сповіщень |
| `feeds/` | прайси, які постачальник надсилає файлом |
| `compare.py`, `report_xlsx.py`, `template.html` | код скрипта і шаблон дашборда |
| `site_template.html` | сторінка входу з паролем для веб-версії |
| `.github/workflows/compare.yml` | розклад і кроки запуску |

## Перший запуск

1. Створіть на GitHub новий приватний репозиторій, наприклад `price-watch`.
2. Завантажте вміст архіву: **Add file → Upload files**, перетягніть усі файли й папки, натисніть **Commit changes**. Папки, назва яких починається з крапки, на деяких системах приховані. Якщо після завантаження в репозиторії немає папки `.github`, створіть файл вручну через **Add file → Create new file**, у полі назви впишіть `.github/workflows/compare.yml` і вставте вміст цього файлу з архіву.
3. Додайте посилання на свій фід у секрети: **Settings → Secrets and variables → Actions → New repository secret**. Назва `MY_FEED_URL`, у поле значення вставте повне посилання на YML-експорт SalesDrive разом із `publicKey`. Посилання на фід Водоспаду вже вписане в `config.json`, окремий секрет для нього не потрібен.
4. Запустіть перевірку вручну: **Actions → Порівняння цін → Run workflow**. Запуск триває одну-дві хвилини.
5. Відкрийте головну сторінку репозиторію. У README з'явиться звіт. Якщо спільних товарів менше, ніж ви очікували, загляньте в `mapping/suggestions.csv`: там товари, які скрипт не наважився зіставити сам.

Далі перевірка запускається сама щодня о 09:30 за Києвом. Посилання на ваш фід лежить тільки в секретах і ніде не світиться, навіть у логах. Щоб звіт відкривався за посиланням з телефону чи комп'ютера, налаштуйте веб-версію з наступного розділу.

## Веб-версія за посиланням

Дашборд публікується як звичайна сторінка на GitHub Pages і відкривається за посиланням з будь-якого пристрою. На безкоштовному тарифі Pages працюють лише з публічних репозиторіїв, тому сторінка лежить в окремому публічному репозиторії, але зашифрована паролем. Без пароля там видно тільки набір символів, а ваші дані, історія і налаштування лишаються в приватному репозиторії.

1. Створіть ще один репозиторій, цього разу **публічний**, наприклад `prices-view`. Нічого в нього не завантажуйте.
2. Створіть токен, яким основний репозиторій записуватиме сторінку: аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**. У **Repository access** оберіть **Only select repositories** і репозиторій `prices-view`. У **Permissions** для **Contents** поставте **Read and write**. Термін дії оберіть найдовший. Скопіюйте токен.
3. В основному приватному репозиторії додайте три секрети:

| Секрет | Значення |
|---|---|
| `DASHBOARD_PASSWORD` | пароль для входу, щонайменше 12 символів, не той, що ви використовуєте деінде |
| `SITE_REPO` | `ваш-логін/prices-view` |
| `SITE_TOKEN` | токен із кроку 2 |

4. Запустіть **Actions → Порівняння цін → Run workflow**. Після кроку «Опублікувати веб-версію» в репозиторії `prices-view` з'явиться файл `index.html`.
5. У репозиторії `prices-view` відкрийте **Settings → Pages**, оберіть **Deploy from a branch**, гілку `main`, папку `/ (root)` і натисніть **Save**.

За хвилину-дві звіт відкриється за адресою `https://ваш-логін.github.io/prices-view/`. Це ж посилання з'явиться вгорі README і в повідомленнях Telegram.

Пароль вводиться один раз на кожному пристрої, якщо лишити галочку «Запам'ятати». Внизу дашборда є посилання «Вийти на цьому пристрої». Щоб забрати доступ у людини, якій ви давали пароль, змініть секрет `DASHBOARD_PASSWORD` і запустіть перевірку: старий пароль і всі збережені входи перестануть працювати. Сторінку оновлюють щоранку, а браузер може кілька хвилин показувати кешовану версію.

Якщо приватність даних не важлива, можна обійтися без пароля і другого репозиторію. Зробіть основний репозиторій публічним, увімкніть у ньому **Settings → Pages** з гілки `main` і папки `/docs`, а в `config.json` поставте `"github_pages": true`. Тоді кожен, хто знайде репозиторій, побачить постачальника, ціни і пари товарів.

## Інші способи дивитися звіт

Короткий звіт з червоними й помаранчевими таблицями видно на головній сторінці репозиторію. Excel відкривається так: клік на `report.xlsx`, потім **Download raw file**. Червоні рядки там теж залиті кольором. Файл `docs/index.html` можна завантажити і відкрити в браузері без інтернету.

## Кілька постачальників

Постачальники перелічені в `config.json` у розділі `suppliers`. Кожен займає один блок:

```json
"suppliers": [
  { "id": "vodospad", "label": "Водоспад", "url": "https://www.vodospad.net.ua/export/prom.xml" },
  { "id": "agrolux",  "label": "Агро-Люкс", "file": "feeds/agrolux.xlsx" }
]
```

| Поле | Що означає |
|---|---|
| `id` | коротке ім'я латиницею без пробілів; воно стоїть у знімках цін і в правилах зіставлення, тому міняти його після першого запуску не варто |
| `label` | назва, яку видно у звітах |
| `url` | посилання на фід або прайс |
| `file` | шлях до файлу в репозиторії, якщо прайс надсилають файлом |
| `columns` | необов'язково: назви колонок прайсу, коли їх не вдається впізнати автоматично |
| `format` | необов'язково: `xml`, `csv` або `xlsx`, якщо формат визначився неправильно |

Якщо один постачальник недоступний, звіт будується без нього, а вгорі з'являється попередження. Решта порівнюється як звичайно.

Порівняння працює однаково для всіх: для кожного постачальника окремо шукаються пари, ведеться своя історія цін і свій журнал змін. У таблиці товар займає один рядок, а кожен постачальник отримує свою колонку з ціною і наявністю.

### Прайс із хмарної папки

Найзручніший спосіб, бо завантажувати нічого не треба: файл лежить у Google Диску, Google Таблиці, Dropbox або OneDrive, а ви чи постачальник просто оновлюєте його на місці. Наступного ранку система бачить нові ціни.

1. Відкрийте файлу доступ за посиланням. У Google це **Надіслати доступ → Усі, хто має посилання → Читач**. Без цього кроку система побачить сторінку входу замість файлу.
2. Скопіюйте звичайне посилання з адресного рядка чи кнопки «Копіювати посилання».
3. Вставте його в `config.json` у поле `url`.

```json
{ "id": "agrolux", "label": "Агро-Люкс", "url": "https://docs.google.com/spreadsheets/d/1AbC.../edit#gid=0" }
```

Посилання на пряме завантаження перетворюється само, скорочувати чи правити його не треба. Працюють:

| Джерело | Що вставляти |
|---|---|
| Google Таблиці | посилання на таблицю; береться той аркуш, який був відкритий, коли ви копіювали посилання |
| Google Диск | посилання на файл XML, CSV або Excel |
| Dropbox | посилання на файл |
| OneDrive і SharePoint | посилання на файл |

Формат визначається за вмістом файлу, тому розширення в посиланні не потрібне. Якщо система помилилась, вкажіть формат прямо: `"format": "csv"`, `"xlsx"` або `"xml"`.

Зручна схема роботи: заведіть у Google Диску папку «Прайси», покладіть туди по одному файлу на постачальника і дайте кожному посилання на його файл. Тоді оновлення прайсу зводиться до заміни файлу в папці з телефона чи комп'ютера.

### Прайс файлом у репозиторії

Другий варіант, якщо хмара не підходить. Формати ті самі: XML, YML, CSV і Excel. Покладіть файл у папку `feeds/` через **Add file → Upload files** і впишіть шлях у `config.json`. Колонки з назвою, ціною, артикулом і наявністю скрипт шукає сам за заголовками, навіть якщо перед ними є шапка з реквізитами. Кодування UTF-8 і Windows-1251, роздільник кома, крапка з комою або табуляція.

Якщо заголовки незвичні, впишіть їх точні назви:

```json
{ "id": "agrolux", "label": "Агро-Люкс", "file": "feeds/agrolux.xlsx",
  "columns": { "name": "Найменування", "price": "Опт", "code": "Артикул", "avail": "Залишок" } }
```

Наявність розпізнається і числом, і словом: `0`, `немає`, `під замовлення`, `відсутній` означають, що товару немає. Порожня клітинка означає, що товар є.

### Закрите посилання на прайс

Коли посилання містить ключ доступу, тримати його в `config.json` не варто, бо файл видно всім учасникам репозиторію, а у веб-версії він не з'являється лише тому, що туди потрапляє готовий звіт. Додайте секрет `SUPPLIER_URLS` і впишіть у нього по рядку на постачальника:

```
agrolux = https://agrolux.example/price.xml?key=...
dnipro = https://dnipro.example/export.csv
```

Поле `url` для цього постачальника в `config.json` тоді можна лишити порожнім.

### Постачальник без фіду: Клуб Рослин

У plants-club.ua немає фіду, тому каталог щоранку збирається прямо з сайту. Окремо налаштовувати нічого не треба, постачальник уже є в `config.json`:

```json
{ "id": "plantsclub", "label": "Клуб Рослин", "scraper": "plants_club",
  "options": { "skip_categories": [], "delay": 0.7, "max_minutes": 40 } }
```

Збирач бере список категорій із карти сайту і проходить кожну сторінками. У списку категорії сайт віддає ціну, артикул, виробника і залишок на складі, тому сторінки окремих товарів не відкриваються. Товар вважається наявним, якщо він активний на сайті і залишок не менший за мінімальне замовлення. Запити йдуть по одному з паузою, щоб не навантажувати сайт.

Усе зібране зберігається в `data/scraped/plantsclub.csv`: назва, артикул, ціна, наявність, залишок і посилання. Цей файл зручно відкрити, якщо хочеться перевірити, що саме побачила система.

| Параметр | Що змінює |
|---|---|
| `skip_categories` | розділи, які не треба обходити, разом із вкладеними; наприклад, `["roslyny"]` прибере всі рослини, якщо ви їх не продаєте, і обхід стане значно швидшим |
| `delay` | пауза між запитами в секундах; менше 0,5 ставити не варто |
| `max_minutes` | після цього часу обхід зупиняється, а звіт будується без Клубу Рослин з попередженням |

Якщо сайт змінить устрій або почне блокувати сервери GitHub, звіт не зламається: він побудується по решті постачальників, а вгорі з'явиться попередження з причиною. При блокуванні допоможе секрет `FEED_PROXY` з українським проксі.

### Орієнтир для порівняння

Коли постачальників кілька, ціни порівнюються з найдешевшим із тих, у кого товар є в наявності. Якщо товару немає ніде, береться просто найдешевший. У таблиці такий постачальник підписаний словом «найдешевший», а колонка «Різниця з орієнтиром» рахується саме від нього.

## Наявність

Наявність показується з обох боків: під вашою ціною і під ціною кожного постачальника. Для цього є окремі фільтри:

| Фільтр | Що показує |
|---|---|
| Немає в наявності ніде | ви продаєте товар, а купити його зараз немає в кого |
| Немає у вас, є в постачальника | товар можна повернути в продаж |
| Лише ті, що є в наявності хоча б в одного | ховає позиції, які зараз не купити |

Товари без наявності з порівняння не викидаються, бо ціна на них однаково змінюється, і це видно в історії.

## Що означають кольори

| Колір | Коли | Що зробити |
|---|---|---|
| червоний | постачальник змінив ціну з минулого запуску, а ваша лишилась такою ж, або ваша ціна нижча за допустиму | оновити ціну в SalesDrive |
| помаранчевий | ваша ціна вища за допустиму | перевірити, чи це свідоме рішення |
| без кольору | ціна в межах норми | нічого |

Позначка «постачальник змінив ціну» тримається до наступного запуску. Якщо ви не відреагували, рядок далі підсвічується за самою різницею цін: червоним, коли ваша ціна нижча, помаранчевим, коли вища. Колонка «Розбіжність, днів» показує, скільки днів поспіль ціна виходить за межі норми. «Змін за 30 днів» рахує, як часто постачальник міняв ціну на цей товар.

## Допустима ціна

Скрипт вважає ціну нормальною, якщо вона лежить у межах:

```
від  ціна постачальника × (1 + min_markup_pct / 100) - tolerance_uah
до   ціна постачальника × (1 + max_markup_pct / 100) + tolerance_uah
```

Зараз стоять нулі, тобто орієнтиром є рівність з ціною постачальника з допуском 1 грн на округлення. Підберіть значення під свою модель:

| Ситуація | `min_markup_pct` | `max_markup_pct` | `tolerance_uah` |
|---|---|---|---|
| у фіді Водоспаду роздрібні ціни, ви продаєте за ними | 0 | 0 | 1 |
| у фіді закупівельні ціни, ваша націнка від 25 до 35% | 25 | 35 | 1 |
| допускаєте знижку до 5% від роздрібної ціни постачальника | -5 | 0 | 1 |
| вища ціна вас не турбує, важливо не продавати дешевше | 0 | 1000 | 1 |

Приклад для другого рядка: постачальник продає за 1 000 грн, норма для вашої ціни від 1 249 до 1 351 грн.

`config.json` можна змінювати просто на GitHub: відкрити файл, натиснути олівець, поправити число і зберегти. Нові пороги спрацюють на наступному запуску. Щоб не чекати до ранку, натисніть **Run workflow**.

## Інші параметри config.json

| Параметр | Зараз | Що змінює |
|---|---|---|
| `my_label` | Садовий Рай | назва вашого магазину у звітах |
| `fuzzy_auto_accept` | 90 | з якої схожості назв пара приймається без підтвердження (за умови однакових номерів моделі) |
| `fuzzy_suggest` | 72 | з якої схожості пара потрапляє на перевірку; нижче скрипт її ігнорує |
| `code_match_min_name_score` | 45 | мінімальна схожість назв при однаковому артикулі; захищає від випадкових збігів артикулів |
| `match_by_supplier_offer_id` | true | чи шукати ваш артикул серед ID товарів постачальника |
| `report_history_days` | 90 | за скільки днів дашборд малює графіки цін |
| `log_days` | 60 | за скільки днів дашборд показує журнал змін; повний журнал завжди в `data/changes.csv` |
| `suppliers` | Водоспад | список постачальників, описаний вище |
| `telegram_only_if_attention` | true | писати в Telegram лише тоді, коли є червоні рядки або попередження |
| `telegram_attach_dashboard` | true | додавати до повідомлення файл дашборда, якщо веб-версію не налаштовано |
| `github_pages` | false | для публічного основного репозиторію без пароля: показувати посилання на його GitHub Pages |

## Як скрипт знаходить спільні товари

Пари шукаються в такому порядку, і перший спосіб, що спрацював, вирішує:

1. Ручне правило з `mapping/mapping.csv`.
2. Однаковий код: артикул, штрихкод або код виробника в дужках у назві, як-от `(0600885B00)`. Назви при цьому мають бути хоч трохи схожі, щоб однаковий внутрішній артикул не склеїв різні товари.
3. Ваш артикул збігається з ID товару у фіді постачальника.
4. Однакова назва без урахування регістру, пробілів, дефісів у моделях і кириличних літер усередині латинських назв моделей.
5. Та сама модель того самого бренду. Наприклад, «Секатор ARS VS-8XZ професійний» і «Секатор ARS VS-8XZ професійний обвідний (АРС VS-8XZ)». Пара приймається, лише коли такої моделі в каталозі постачальника більше немає, а в його назві немає слів на зразок «лівша», «лезо», «набір» чи «кобура», які означають інше виконання або запчастину.
6. Схожа назва: схожість від 90% і однакові номери моделі.

Високої схожості назв мало, бо «Обприскувач Marolex Titan 20 л» і «Обприскувач Kwazar Titan 20 л» різняться на 5%, хоча це різні товари. Тому автоматична пара скасовується, якщо спрацювала хоча б одна з перевірок:

| Перевірка | Приклад пари, яка не пройде |
|---|---|
| різні об'єми, ваги чи розміри | «Ураган Форте 5 л» і «Ураган Форте 1 л» |
| різні одиниці при однаковому числі | «Ураган Форте 1 л» і «Ураган Форте 1 кг» |
| бренд є лише в одній назві або бренди різні | «Свердло 5 мм Bosch» і «Свердло 5 мм Makita» |
| різні коди виробника в дужках | «Лобзик GST 160 (0601518000)» і «Лобзик GST 160 (0601518001)» |
| слово, якого немає в другій назві | «Секатор ARS VS-8Z лівша» і «Секатор ARS VS-8Z» |

Одиниці зводяться до спільної основи, тому «0,5 л» і «500 мл» вважаються однаковим об'ємом. Розмір, вказаний лише з одного боку, конфліктом не рахується: «Дриль Bosch 600 Вт» і «Дриль Bosch 600 Вт з патроном 13 мм» залишаються парою. Слова на кшталт країни походження, «оригінал» чи «новинка» на зіставлення не впливають.

Кожна перевірка не відкидає товар, а переводить пару на ручне підтвердження з поясненням причини. Тому в перші дні список пар на перевірку буде помітним, зате хибних зіставлень не буде. Підтверджена пара залишається в `mapping/mapping.csv` назавжди.

Товари без ціни в одному з фідів не порівнюються, їхню кількість видно в попередженнях. Товари, яких немає в наявності у постачальника, порівнюються, а в дашборді їх можна сховати галочкою «Лише ті, що є в наявності у постачальника».

## Пари на перевірку і ручні правила

Сумнівні пари скрипт не порівнює, доки ви їх не підтвердите. Список оновлюється після кожного запуску і лежить у `mapping/suggestions.csv`, а також на вкладці «Пари на перевірку» в дашборді.

Кілька пар простіше підтвердити на GitHub. Відкрийте `mapping/suggestions.csv`, натисніть олівець і на початку рядка, перед першою комою, впишіть `так` або `ні`:

```
рішення,схожість,мій_id,id_постачальника,мій_товар,...
так,92.7,1014,50003,Секатор Gardena B/S XL,...
ні,79.1,1005,40003,Степлер садовий Tapener MAX HT-R,...
```

Під час наступного запуску рішення перейдуть у `mapping/mapping.csv`, а файл пропозицій очиститься.

Для десятків пар відкрийте дашборд, позначте пари галочками і натисніть кнопку копіювання з позначкою «так» або «ні». Потім відкрийте `mapping/mapping.csv` на GitHub, вставте скопійовані рядки в кінець файлу і збережіть.

Формат `mapping/mapping.csv`:

| Рядок | Що означає |
|---|---|
| `1005,vodospad,40003,так,` | порівнювати ваш товар 1005 з товаром 40003 у Водоспаді, навіть якщо скрипт знайшов інший або нічого не знайшов |
| `1006,vodospad,40004,ні,` | ніколи не зіставляти цю пару; скрипт шукатиме іншу |
| `1010,vodospad,*,ні,` | не порівнювати ваш товар 1010 з жодним товаром Водоспаду |
| `1010,*,*,ні,` | взагалі не порівнювати ваш товар 1010 |

Перше число означає `id` товару у вашому фіді SalesDrive, друге це `id` постачальника з `config.json`, третє це `id` товару в його фіді. Усі вони показані в дашборді під назвою товару. Коментар в останній колонці необов'язковий. Якщо колонку з постачальником лишити порожньою, правило застосується до першого зі списку, тому старі файли читаються без переробки. Якщо скрипт сам зіставив неправильну пару, додайте для неї рядок з `ні`.

Файли можна правити і в Excel. Скрипт розуміє коми та крапки з комою, кодування UTF-8 і Windows-1251.

## Сповіщення в Telegram

1. Напишіть у Telegram боту @BotFather команду `/newbot`, придумайте назву і скопіюйте токен.
2. Напишіть своєму новому боту будь-яке повідомлення. Для робочої групи додайте бота в групу і напишіть щось там.
3. Відкрийте в браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть фрагмент `"chat":{"id":...}`. Число після `id` і є chat_id, у групи воно від'ємне.
4. Додайте секрети `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID` так само, як `MY_FEED_URL`.

Бот пише лише тоді, коли є червоні рядки або попередження. Якщо веб-версію налаштовано, в повідомленні буде посилання на неї, інакше бот додасть файл дашборда. Щоб отримувати повідомлення щодня, поставте `"telegram_only_if_attention": false`.

## Розклад

Час запуску задає рядок `cron: "30 6 * * *"` у файлі `.github/workflows/compare.yml`. GitHub рахує час за UTC: 06:30 UTC відповідає 09:30 за київським літнім часом і 08:30 за зимовим. Для запуску о 07:00 за літнім часом впишіть `"0 4 * * *"`. У години пікового навантаження GitHub може запускати заплановані задачі із запізненням.

## Якщо щось не працює

Текст помилки видно в **Actions**: відкрийте запуск і крок «Порівняти ціни і зберегти історію». За стандартних налаштувань сповіщень GitHub також надсилає лист, коли запланований запуск падає.

| Що бачите | Причина | Що зробити |
|---|---|---|
| «Не задано посилання на фід» | секрет не додано або в назві помилка | перевірте, що секрет називається саме `MY_FEED_URL` |
| «У прайсі не знайдено колонок з назвою і ціною» | заголовки прайсу незвичні або файл порожній | впишіть назви колонок у розділ `columns` цього постачальника в `config.json` |
| «Файл не знайдено» | шлях у `config.json` не збігається з реальним | перевірте назву файлу в папці `feeds/`, регістр літер має значення |
| «Посилання відкриває веб-сторінку, а не файл» | у хмарного файлу закритий доступ | поставте **Усі, хто має посилання → Читач** і повторіть запуск |
| «Не вдалося завантажити фід» з кодом 403 або «у відповіді немає товарів» | сайт не віддає фід серверам GitHub або посилання застаріло | відкрийте посилання в браузері; якщо фід там є, додайте секрет `FEED_PROXY` з українським проксі у форматі `http://логін:пароль@адреса:порт` |
| помилка з `403` і `github-actions[bot]` під час збереження | воркфлоу не має права на запис у репозиторій | **Settings → Actions → General → Workflow permissions → Read and write permissions** |
| попередження «Спільних товарів стало N замість M» | один із фідів віддався не повністю | звіт побудовано, але перевірте фід; наступний запуск зазвичай усе виправляє |
| крок «Опублікувати веб-версію» падає з `403` або `Permission denied` | токен не має доступу до `prices-view` або його термін минув | створіть новий токен з **Contents: Read and write** саме для цього репозиторію і замініть секрет `SITE_TOKEN` |
| «Не задано секрет DASHBOARD_PASSWORD» | є `SITE_REPO` і `SITE_TOKEN`, але немає пароля | додайте секрет `DASHBOARD_PASSWORD`; без пароля звіт не публікується |
| посилання на веб-версію відкриває 404 | Pages у `prices-view` не увімкнено або сторінка ще збирається | перевірте крок 5 розділу «Веб-версія за посиланням» і зачекайте кілька хвилин |
| заплановані запуски зупинились | GitHub вимикає розклад у публічному репозиторії після 60 днів без активності, наприклад якщо весь цей час запуски падали | **Actions → Порівняння цін → Enable workflow** |

Якщо ви саме редагували файли, коли йшов запуск, скрипт помітить це перед збереженням, перерахує все на свіжій версії і збереже без конфлікту.

## Історія

Кожен запуск додає файл `data/snapshots/РРРР-ММ-ДД.csv` з цінами всіх спільних товарів. Повторний запуск того ж дня перезаписує знімок і не дублює журнал змін. Історія зберігається без обмежень: дашборд малює графіки за 90 днів, Excel показує ціни по днях за останній місяць, повний журнал лежить у `data/changes.csv`.

## Запуск на комп'ютері

Потрібен Python 3.10 або новіший.

```bash
pip install -r requirements.txt
MY_FEED_URL="посилання на фід" python compare.py
```

У Windows PowerShell друга команда виглядає так:

```powershell
$env:MY_FEED_URL="посилання на фід"; python compare.py
```

Замість посилання можна вказати шлях до збереженого XML-файлу. Локальний запуск змінює файли в `data/`, `docs/` і `mapping/`, тому не комітьте їх після тестових прогонів.
